## 1. 产品定义

### 1.1 一句话

> **存念小罐**
> 每周存一点，留给未来的自己。

把一生画成 80 × 52 = 4160 个格子，每周点亮一格。它让你看见有限，也让你安放当下。

**名字的取舍**：「存念」是动作也是名词——存下的念头，存下的念想；「小罐」把它变成一件可以捧在手里的东西，不宏大、不严肃、有盖子，可以随时打开看看。副标题只说一件事：**存，是为了将来的自己。** 不提「珍惜时间」「记录人生」这类大词。

### 1.2 它不是什么

- **不是时间管理工具**：不排日程、不做待办、不计算效率。
- **不是打卡软件**：没有连续天数、没有火焰、没有「已坚持 365 天」。
- **不是社交平台**：没有广场、没有排行榜、没有关注，**不做卡片分享**。
- **不是 AI 人生导师**：不做「你的人生总结」，不给建议，不打分。

### 1.3 一条不能越的线：不做任何形式的分享

**这是属于个人的东西。** 一旦能分享，写下的话就开始为别人而写。

- 不做周卡分享图、不做长图导出到社交平台
- 不做好友、不做互动、不做「看看别人这周写了什么」
- 同行的人**只能看到进度条，看不到一个字**
- 唯一的对外输出是**个人备份导出**（JSON / Markdown），它不是分享功能

唯一例外：打印自己的人生海报给自己。那是实体的、私人的、挂在自己墙上的。

### 1.4 五条设计信条

1. **网格是背景，记录是前景。** 日常打开看到的是本周，不是墓碑。
2. **不做连胜，只记累计。** 断掉一周不是失败，断掉一周就是生活本身。
3. **允许空白。** 空白格可以没有字。
4. **数据比 App 活得久。** 本地优先、纯文本、随时导出。
5. **安慰优于激励。** 面对疲惫的人，给承认；面对顺遂的人，给意义。

### 1.5 一条交互总原则：把「阈值」从用户手里拿走

不要问用户「你要不要看剩余时间」——这个选择本身就是压力，而且焦虑时大部分人会选「不看」，然后永远不看。

**默认不给，想要的人自己伸手去拿。** 剩余时间只有一个出口：鼠标悬停在顶部进度条上。抬手即得，移开即散。

同理，不做「问候语预览」「主题切换」这类调试性质的选项。**产品不该让用户调教它怎么爱自己。**

## 2. 用户与三种流失

### 2.1 目标用户

- 25–45 岁，有过写日记/手帐经历但没坚持下来的人；
- 正在经历某个人生节点（生育、亲人老去、职业转折）的人；
- 对「时间感」敏感、读过《四千周》一类内容的人。

### 2.2 核心洞察：日记不是死于「不会写」，是死于三种时刻

| 流失形态 | 用户心里的话 | 传统日记 App 的反应 | 存念小罐的对策 |
|---|---|---|---|
| **压力型** | 「太累了，今天不想面对自己」 | 弹提醒：「你已 12 天未打卡」 | 降低门槛：点一个点就算记录；问候改为照看 |
| **顺遂型** | 「日子挺好的，记这个有什么用」 | 无反应，静默流失 | 给意义：「顺的日子最容易被忘掉」 |
| **遗忘型** | 「啊，忘了」 | 推送轰炸 | 环境入口；回来时零指责 |

**结论：留存的关键不在功能，在「打开的那 3 秒里，它对我说了什么」。**

| 区 | 宽 | 内容 |
|---|---|---|
| 左栏 | 264 | 品牌（含**当前年龄**）· 搜索 · **人生的周**（一年一页，每页 52 周，`‹ ›` 翻年；每行 7 个刻度＝这 7 天有没有记）· 今年存下 N 个念头 |

| 右栏 | 360 | **人生周历**（52×77 点阵）· 图例 · 已走过 / 还剩下 / 已用掉 · 人生阶段 · 同行 · 往年这一周 |

**左中右的分工**：左边是索引，中间是内容，右边是坐标。写的时候只看中间；想知道自己走到哪儿了，看右边。
### 3.1 四套皮肤

| 皮肤 | 模式 | 强调色 |
|---|---|---|
| 01 纸白 | 浅 | `#B85C36` 陶土 |
| 02 夜窗 | 深 | `#D9A05B` 暖金 |
| 03 雾青 | 浅 | `#3F7061` 松绿 |
| 04 靛蓝 | 浅 | `#3C5B85` 靛青 |

同一套变量名，一对一替换：`--page / --surface / --ink / --accent / --line / --grid-past / --grid-future / --grid-now`。**换肤只换变量，不换结构。**

### 3.2 标识

一只达摩式的圆罐：陶土罐身、纸白脸、双眼与眉、顶部一道投币口。罐身色 `#B85C36` **不随皮肤变**——它是这只罐子唯一的固定色。

- 应用图标：圆角方形（半径 22.7%）/ 直角方形 / 圆形三版
- 界面内分级：≥34px 用完整版（眉 + 眼 + 投币口）；15–33px 只留罐身与双眼；≤14px 再简化
- 不做：拉伸、投影、发光、渐变、3D、改罐身色、把投币口转到侧面

## 4. 核心系统 A：人生周历

### 4.1 规格

- **52 列 × 80 行 = 4,160 格**（80 年），一格 = 一周。
- 每行一年，从左到右是这一年的 52 周。
- 点阵：每点 3px、间隙 1px，整块 **207 × 308 px**，放在右栏。
- 每 10 年一条细横线作刻度。

### 4.2 三种状态

| 状态 | 色 | 语义 |
|---|---|---|
| 已过 | `--grid-past` | 走过的日子 |
| 本周 | `--grid-now`（陶土色） | 你正在这一格 |
| 未到 | `--grid-future` | 还没发生 |

**取消了「有记录 / 无记录」这第四种状态。** 在 3px 的点上，你看不出区别，也不该看出区别——记录在中栏，坐标在右栏，各司其职。

### 4.3 点击定位

点阵太小，不能要求用户点中一个 3px 的点。所以按坐标换算：鼠标位置 →（行, 列）→ 第几周 → 那一天。落在哪算哪，不需要精确。

### 4.4 不算「还剩多少」★（v1.3）

这一版把「人生阶段」和「剩余年数」全部拿掉了。

**软件只是在提醒人珍惜时间，没有资格替人定义「你正处在青年」，也没有资格说「你还剩 42 年」。** 人的年龄、寿命、怎么过，是每个人自己的事；软件每天报一次倒计时，既越界，也让人焦虑。

右栏只留两个诚实的数字：**已存下多少念头、点亮了多少天。** 外加一句「1,798 周里，有 115 天留下了字。」——它描述的是你做过什么，不是你剩下什么。

「加油，陌生人！」保留，但只在把鼠标放到周历上时才出现。

### 4.5 左右两栏用同一套编号 ★（v1.3）

左栏的周列表和右栏的点阵必须能对上，否则用户要在两套系统之间换算。

统一为**「人生的第 N 周」**：

- 左栏：`第 1,798 周` + `11.16 – 11.22`（日期范围始终跟着，方便认）
- 右栏：点阵的同一个索引就是同一个点，选中的那格会描边
- 标题栏：也是同一个数

原来左栏用的是「2026 年第 47 周」（ISO 周），右栏用的是人生第几周——两个编号叠在一起，谁也看不懂谁。现在只剩一套。

### 4.6 年龄放在哪 ★（v1.4）

> v1.5 起，左栏的周列表改为**一年一页**：一页 52 行，顶部 ‹ 人 生 的 周 › 翻年，下面标注「第 35 年 · 1,769–1,820 周」。4,160 行一次铺出来既慢又难找，按年翻更接近人记日子的方式。

年龄放在**左栏品牌下面**：`存念小罐` / `34 岁 · 4,160 周`。

选这里的理由：

- 它和「这是谁的罐子」在一起，是身份，不是评价。
- 它只陈述事实，不推导「还剩多少」，不替代用户判断。
- 它不随查看的日期变——「目前的年龄」就该是现在，不是你在看的那一天。

**不放在中栏**：中栏是内容，日期一变年龄也该变，会变成一堆数字里的一个。
**不放在右栏**：右栏是坐标，放大数字会重新变成倒计时的邻居。

## 5. 核心系统 B：记录与周卡

### 5.1 三层时间

| 层 | 作用 | 门槛 |
|---|---|---|
| 日 | 随手捕获 | 点一个感觉 / 说一句话 / 放一张图 |
| 周 | 核心原子，**自动汇编** | 可选补一句关键词 |
| 岁 | 年度总览 | 自动生成 |
| 生 | 全景 | 主动凝视 |

**周页面是「汇编」出来的，不是「填」出来的。** 周日不写没有任何惩罚。

### 5.2 周卡构成

- 头部：第 N 周 · 岁数 · 日期区间 ·「正在这里」· 上一周/下一周
- 周进度条：7 段，走过的高亮，今天最深
- 记录流：日期 + 心情 + 正文 + 图片 + 「编辑」
- **回声**：底部固定显示「一年前的这一格」
- 输入区：一句话 + 5 档心情 + 「＋图片」+「记录」

### 5.3 心情（mood）★（v0.5）

5 档，从冷到暖，用颜色区分，界面上不常驻文字标签。

| 档 | 名称 | 色值 | 观感 |
|---|---|---|---|
| 1 | 很低落 | `#8e9aa6` | 冷灰蓝 |
| 2 | 有点累 | `#a8a79b` | 灰绿 |
| 3 | 平平 | `#c2b49c` | 米灰 |
| 4 | 不错 | `#c98f63` | 暖橙 |
| 5 | 很好 | `#ab5330` | 深赭 |

- 记录行里日期旁边有 5 个点，点亮的前 N 个**按各自档位着色**——一眼看出那天的心情温度。
- **悬停即时显示档位名称；点击后鼠标不移动也会立刻弹出**，停留约 1.7 秒后淡出。
  - 不能用浏览器原生 `title`：原生提示要重新移入才刷新，点完必须挪开鼠标再放回来，交互是断的。
  - 自绘浮层由程序控制位置与时长，点击与悬停走同一条通路。
- 输入区与问候层同色系，选中即着色。

不给用户贴情绪词，避免「我今天到底是什么情绪」的认知负担；但悬停时要查得到——**颜色负责扫一眼，文字负责确认。**

mood 只用于：格子深浅、问候分支。**不做统计图表，不做情绪曲线。**

### 5.4 一天只许一张图

| 项 | 规则 |
|---|---|
| 上限 | **每个自然日最多 1 张**，跨全应用计数 |
| 入口 | 输入区「＋ 一张图」 |
| 选图后 | 先进入待确认缩略图，可点 × 换掉；**只有按下「记录」才真正用掉** |
| 用掉之后 | 按钮变灰，文案改为「今天的那一张已用」 |
| 处理 | 客户端压缩到长边 ≤ 900px、JPEG 质量 0.7 |
| 已用时的点击 | 只提示「今天那一张已经用掉了。」不提供绕过 |

**为什么是一张**：无限上传 = 相册搬家，等于没选。只能一张，人才会真的挑——挑的过程就是「这一天到底什么值得留下」的过程。**不留遗憾的前提是，先有过取舍。**

### 5.5 编辑：任何一天都可以改 ★（v0.4）

| 项 | 规则 |
|---|---|
| 范围 | **所有时间的所有记录**，不限当天、不限近期 |
| 入口 | 记录右上角「编辑」（悬停出现） |
| 可改 | 正文、心情、移除图片 |
| 图片 | 「移除这张图」需点保存才生效；移除后该日的额度释放 |
| 删除 | 两步确认（第一次点变「再点一次删除」），3 秒后自动复位 |
| 不做 | 不改日期、不做版本历史（v1 范围） |

**为什么必须给这个权力**：昨天写错了、去年写得太冲、十年前那句现在看着刺眼——如果连自己的本子都不能改，这就不是本子，是档案。**日记的主权必须完整。**

### 5.6 待确认缩略图

选图后不直接入库，而是在输入区显示缩略图 + ×。可以反复换，直到按下「记录」。关掉 App 不会用掉当天额度。

## 6. 核心系统 C：情绪陪伴系统 ★

> 打开 App 的第 3 秒，它必须像一个人，而不是一个计数器。

### 6.1 七条设计原则

1. **不追问理由，不计算缺席。** 永不出现「你已 N 天未记录」。
2. **一次只说一句。** 多一句就是压力。
3. **只谈今天，不谈欠账。**
4. **有记忆，但不炫耀记忆。**
5. **可回应，也可沉默。** 永远有「先不写，进去看看」的出口，且不产生任何记录。
6. **安慰优于激励**（注意：这是兜底原则，不是默认语气——见 6.3）。
7. **三次沉默原则。** 连续 3 次忽略问候，降级为「只点亮当前格，不说话」，两周后再试。

### 6.2 六个声音：性别 × 年龄段

问候不是一套文案，是**六套**。同样的意思，用不同的人说出来，必须像不同的人。

| 模块 | 年龄段 | 声音特征 |
|---|---|---|
| `f_young` | 30 岁以下女性 | 轻盈、亲近，句子短，不用大词 |
| `m_young` | 30 岁以下男性 | 干脆、少矫情，不哄也不劝 |
| `f_mid` | 30–59 女性 | 体谅、承认辛苦，句子具体 |
| `m_mid` | 30–59 男性 | 克制、直给，不煽情 |
| `f_old` | 60 岁以上女性 | 温和、念旧，语速慢 |
| `m_old` | 60 岁以上男性 | 简短、沉稳，少形容词 |

同一状态、六种说法（以「低落」为例）：

| 模块 | 说法 |
|---|---|
| f_young | 上次你说有点累。 / 今天好点了吗？不用说清楚，点一下也行。 |
| m_young | 上次你说不太行。 / 今天怎么样？点一下就行，不用说。 |
| f_mid | 上次你说有点累。 / 今天呢？如果还是累，就点一下，不用写字。 |
| m_mid | 上次你说累。 / 今天好点没？点一下就行。 |
| f_old | 上次你说有点累。 / 今天好些了吗？点一下就好，不用写。 |
| m_old | 上次你说不太舒服。 / 今天怎么样？点一下就行。 |

**六种说法的「意思」必须完全一样**，差别只能在语气和用词。不能给某个群体额外的怜悯，也不能给某个群体额外的说教——那是偏见，不是体贴。

### 6.3 语气规则：默认鼓励，低落才安慰 ★（v0.4）

| 条件 | 语气 |
|---|---|
| 上次记录 mood ≤ 2 | **安慰**（`low`） |
| 其余所有情况 | **鼓励** |

这条规则优先于一切时间判断：**心情低落的人，无论隔了多久，都先被接住，而不是先被欢迎回来。**

因此状态机调整为：

| 优先级 | 状态 | 判定条件 | 语气 |
|---|---|---|---|
| 1 | 初遇 | 无任何记录 | 鼓励 |
| 2 | 今日已达 | 今天已有记录 | 鼓励（收束） |
| 3 | **低落** | **上次记录 mood ≤ 2** | **安慰** |
| 4 | 深夜 | 23:00–04:00 | 体谅 |
| 5 | 顺遂 | 距今 ≤ 1 天且 mood ≥ 4 | 鼓励 |
| 6 | 稳定 | 距今 1–2 天 | 鼓励 |
| 7 | 周中 | 距今 3–7 天 | 鼓励 |
| 8 | 短暂中断 | 距今 8–21 天 | 鼓励（免责） |
| 9 | 长期中断 | 距今 22–60 天 | 鼓励（迎接） |
| 10 | 久别 | 距今 > 60 天 | 鼓励（归零） |

**鼓励 ≠ 打鸡血。** 鼓励的做法是「允许 + 认可」，不是「加油 + 你可以的」。例如：

- ✅ 「这一周还开着呢。/ 一句就够。写下来，这周就不算白过。」
- ❌ 「新的一周开始啦，要加油哦！」

### 6.4 回应后的第二句

| 选择 | 回应 |
|---|---|
| 1–2 | 嗯，收到了。今天不用再做什么了。 |
| 3 | 平平的日子也算数。 |
| 4 | 挺好的。让这一格亮一点。 |
| 5 | 很好。这样的日子，值得留一盏灯。 |

### 6.5 话术编写规范

- 单句 ≤ 18 字；副句 ≤ 30 字。
- 不用感叹号（**唯一例外**：进度条气泡的「加油，陌生人！」）。
- 不用表情符号。
- 禁用词：「应该」「坚持」「自律」「目标」「打卡」「进步」。
- 不出现具体天数（除非用户主动查看统计）。
- 每句最多一个「你」。
- 结尾落在「今天 / 这一格 / 现在」。

### 6.6 反模式（出现即打回）

| ❌ 错 | ✅ 对 | 原因 |
|---|---|---|
| 你已 37 天没有记录了！ | 有阵子没见了。 | 前者是审判 |
| 坚持就是胜利，加油！ | 今天不用再做什么了。 | 前者是鸡汤 |
| 今天也要元气满满 💪 | 这么晚还醒着。 | 前者油腻且不允许低落 |
| （自动弹出年度统计） | （用户主动点开才看） | 数据可视化会变成考核 |
| 🔥 连续记录 12 周 | 你已经点亮了 12 格。 | 连胜机制制造断签焦虑 |
| 要不要开启「温柔模式」？ | （没有这个选项） | 让用户自己定阈值 |
| 宝妈你好，今天也要照顾好自己哦 | 这一周还没走完。 / 不用写长，一句就够。 | 用身份标签代替人 |

### 6.7 安全边界

- 不做心理诊断、不做情绪评分、不上报。
- 连续 5 条 mood = 1 且正文含自伤相关词 → 显示安静卡片并给出当地心理援助热线与就医建议。
- **热线号码必须在发布前逐个核验，不得用占位号码上线。**
- 该卡片不可分享、不可导出。

## 7. 核心系统 D：首次引导

### 7.1 设计立场：空白是产品的第一句话

第一次打开，4160 格里只有一格亮着，其余全空。**这个画面本身要保留**，不要用示例数据盖住它。

### 7.2 两步流程（v0.4：去掉所有说明文字）

```
第 1 步        你是
             [ 女 ]   [ 男 ]

第 2 步       出生的年月
        [1995] 年  [6] 月
              [ 开始 ]
```

**为什么把所有说明文字删掉**：

> 「加了这句话就好像有人在前面盯着他问；取消了，才有自己问自己的感觉。」

说明文字会把「自我确认」变成「被问卷」。删掉之后，屏幕上只有问题本身，用户是在问自己，不是在回答系统。

同理，不写「仅用于调整语气」「我们不会用于其他用途」——一旦开始解释，就有了「系统」的存在感。

### 7.3 只问这两项

| 信息 | 用途 | 不问的理由 |
|---|---|---|
| 性别 | 决定问候模块（6 选 1） | 只影响语气，不用于画像 |
| 出生年月 | 决定格子起点与年龄段 | 是一切的前提，无法后置 |

其余一律不问。**首屏每多一个输入框，就多一成的人走掉。**

## 8. 核心系统 E：同行

### 8.1 它解决什么

「你只剩 2,362 周」是抽象数字，人对抽象数字无感。
「父亲那条进度条已经走到五分之四」是具体画面，人对画面有感。

### 8.2 规格

| 项 | 规则 |
|---|---|
| 位置 | 主区顶部一行，标题「同行」 |
| 上限 | **5 人**，达到上限后 ＋ 变灰，点击提示「最多五个。」 |
| 单人体量 | 名字 + 62px 进度条 + 年龄，约 130px |
| 必填 | 称呼 + 出生年份 + 关系（亲人 / 朋友 / 爱人） |
| 揭示 | 悬停显示「亲人 · 已过 64 年 · 还剩 16 年」 |
| 空态 | 「还没有添加。」+ ＋ |
| 管理 | 设置面板内增删 |

**为什么是 5**：这个列表不是通讯录，是「你心里最放不下的那几个人」。给到 20 个，它就变成了联系人管理；只给 5 个，逼你选。

### 8.3 一条硬边界：只同步时间，不同步内容

**同行的人只显示进度条，不显示任何日记内容。**

1. 一旦能看对方在写什么，就变成社交产品，用户会开始表演。
2. 日记的真实性依赖「没人看」。
3. 「父亲剩 20 年」是提醒，「父亲今天写了什么」是监视。

v1 不做、v2 不做、**不做**。

## 9. 核心系统 F：手动同步 ★（v0.7）

### 9.1 立场：同步是一次决定，不是一条后台流水线

不做自动同步、不做账号、不做云。同步由用户主动发起，一次一个决定。

理由有三：

1. 自动同步必然需要一个常驻的中间人（服务器或常开设备），那就已经离开「只在本地」了。
2. 日记不需要实时一致。你在地铁上写的那条，回家再传完全来得及。
3. **同步是需要人做判断的事**——两边都有改动时，机器不该替你决定留下谁的。

### 9.2 罐子码：不要账号，要一只罐子 ★（v0.8）

不做账号，但必须回答一个问题：**怎么知道这个文件是我的？**

答案是一只「罐子码」——16 位随机字符（Crockford Base32，去掉了容易认错的 I / L / O / U），四位一组：

```
XF2C-7Q9M-3KR4-T8B2
```

| 项 | 规则 |
|---|---|
| 生成 | 首次打开时本机随机生成，**不上传、不登记、没有服务器知道它** |
| 作用一 | **身份**：两台设备的码相同，才是同一只罐子 |
| 作用二 | **加密**：同步文件用它派生 AES-256-GCM 密钥 |
| 展示 | 默认打码，点「显示罐子码」才展开，并提示别截图 |
| 配对 | 旧设备显示二维码 → 新设备「扫码」；也可以手抄那 16 位 |
| 更换 | 换码之后，旧文件不再能导入——这是特性，不是 bug |

**为什么码本身就是密钥，而不是一个 ID**

如果它只是个 ID，文件仍然是明文。你把它丢进微信传给自己，腾讯的服务器上就多了一份明文日记——「不存云端」立刻破功。

码即密钥，文件出门就是密文。**经过谁的服务器都不怕。**

**为什么不做非对称加密**

这个场景里只有「我自己的几台设备」，没有第三方。对称密钥够用，用户只需要保管一串字符。非对称解决的是「别人能看、不能改」，这里没有别人。

**代价**

码泄露 = 数据可被解密（前提是对方还拿到了文件）。所以默认打码、提示别截图。

**二维码（v0.9）**

展开罐子码时同时画出一张二维码，另一台设备点「扫码」直接读取，不用手抄。

- 实现：**自己写的 QR 编码器**（Version 2 / EC-L / byte mode），不引任何外部库——一个连 CDN 都不连的 App，不该为了一个二维码去联网。
- 扫码端用浏览器的 `BarcodeDetector`；**不支持时按钮不出现**，退回手抄，不会给一个点了没反应的按钮。
- 注意：相机需要 https 或 localhost，用 `file://` 直接打开时可能拿不到摄像头（扫码会失败，手输仍然可用）。
- 二维码和那串字符是同一把钥匙，**截图发人等于把钥匙发人**。

**换码与找回（v1.0）**

码泄露了怎么办？必须先承认一个事实：**已经导出去、并且码已经泄露的文件，换码救不回来**——文件在对方手里，钥匙也在。任何声称能"作废已泄露文件"的设计都是骗人的。

所以换码只做两件事：

| 动作 | 作用 |
|---|---|
| **换一只新罐子** | 生成新码，**以后**导出的文件用新钥匙；另一台设备需重新加入 |
| **用旧码打开** | 导入时若解不开，显示该文件所属罐子的指纹（明文前 4 位），允许输入旧码把它打开 |

第二条才是真正的「退路」：换码之后，你手里那些用旧码导出的文件不会变成砖头。

**换码不改数据**：本地记录本来就是明文存在设备上的，罐子码只负责传输加密。换码不涉及重新加密，也不会丢数据——这一点必须让用户看得见，否则他会以为换码会丢东西而不敢换。

### 9.3 流程

```
A 设备：同步 → 导出这台        → 得到一个 .json 文件
        ↓ 隔空投送 / U 盘 / 微信传给自己 / 局域网共享
B 设备：同步 → 导入另一台 → 看到差异 → 三选一
```

全程没有任何服务器参与，文件怎么传由用户决定。

### 9.4 三选一

导入后先展示差异，再让用户选：

| 选项 | 行为 | 什么时候选 |
|---|---|---|
| **用对方的，覆盖这台** | 本机数据被对方整包替换 | 这台是旧的 / 装错了 / 想重置 |
| **合并两边** | 按 id 求并集，同一条取较新的那份 | 两台都有新记录（最常用，默认高亮） |
| **用我的，覆盖另一台** | 不改本机，导出一份本机的包 | 确认本机才是对的 |

第三个选项容易被忽略，但它是关键：**「覆盖」必须是双向的**，不能只允许外来数据覆盖本地。

### 9.5 合并规则

| 项 | 规则 |
|---|---|
| 匹配 | 按记录 `id`（UUID），不按周序号、不按下标 |
| 冲突 | 同一条两边都改过 → `updatedAt` 较新的胜（**整条替换，不做字段级合并**） |
| 删除 | 删除写墓碑 `deleted{id: timestamp}`；两边都有墓碑时取较晚的 |
| 复活 | 墓碑时间 ≥ 对方记录的更新时间 → 不复活 |
| 同行的人 | 按 id 求并集，超过 5 人则截断 |
| 生日 / 性别 | 合并时以本机为准；「覆盖」时以对方为准 |

**为什么不做字段级合并**：正文是一个整体，把两句不同的话拼在一起只会得到一句谁也不认识的话。整条取新的，至少还是「一个人的一句话」。

### 9.6 数据要求（同步的前提）

同步能成立，靠这三样东西，缺一不可：

1. **每条记录有全局唯一 id**——不是数组下标，不是「第几周第几条」。
2. **每条记录有 updatedAt**——用来判新旧。
3. **删除留墓碑**——否则对方那条会被「合并」回来。

这三项与界面无关，但必须在第一版就做对，否则以后所有同步都是错的。

### 9.7 已知限制

- **图片让文件变大**：一天一张，一年约 36MB，同步包会跟着变大。P1 做「只同步文字」选项。
- **不是实时的**：两台设备在两次同步之间必然不一致，这是代价也是特性。
- **需要人记得同步**：可在周提醒里加一句「这周同步过吗」，但绝不强制。

## 10. 核心系统 G：开启动画与本地身份 ★（v1.1）

### 10.1 开启动画

打开时一段约 2.8 秒的开场，然后把纸从中间分开，露出里面。

| 时间 | 画面 |
|---|---|
| 0.0s | 纸色底，标识与字标淡入；副标题下方一条进度条开始走 |
| 0.5s | 「存念小罐」字距由松收拢，浮现 |
| 0.9s | 副标题淡入 |
| 1.2s | 一条细线从左向右生长 |
| 2.2s | 「今天这一格，还空着。」淡入 |
| 2.5s | 内容淡出，纸从正中裂开，向上下分开 |
| 3.3s | 露出后面的东西（门，或主界面） |

- 点任意位置或按 Esc / 空格 / 回车跳过
- 尊重 `prefers-reduced-motion`：缩短为 0.9 秒
- 全程只有四行字——这是唯一一段「产品在解释自己」的地方，所以宁可少说

**为什么是「开罐」而不是「加载」**：门从中间分开这个动作，是「打开一只罐子」的隐喻。加载条让人等，开门让人想进去。

### 10.2 本地身份：账号 + 密码

不做账号体系（见 §9.1 的立场），但需要一个**本地身份**，用来把数据在磁盘上锁起来。

| 项 | 规则 |
|---|---|
| 账号 | 自己起，只在本机，不上传 |
| 密码 | 至少 6 位，与账号一起参与派生 |
| 密钥 | PBKDF2-SHA256(账号 + `\0` + 密码, 随机盐, 200000 次) → AES-256-GCM |
| 落盘 | localStorage 里只有 `{cun, salt, iv, data}`，**没有任何明文** |
| 验证 | 账号或密码错一位，解密直接失败；不需要另存密码哈希 |
| 找回 | **没有**。忘了就打不开 |

**为什么不用「密码哈希」验证**：那意味着数据本身仍是明文，密码只是一道门帘——打开开发者工具就全看见了。这里让密码成为密钥的一部分：**没有密码，磁盘上那串字节就是噪声。**

**为什么账号也参与派生**：这样「换个账号试试」和「换个密码试试」一样打不开；账号是密钥的一半，而不只是一个名字。

### 10.3 首次打开的顺序

```
开启动画
  ↓
第一次打开：设账号 + 密码
  ↓
你是（性别）
  ↓
出生的年月
  ↓
主界面（空白，只有一格亮着）
```

之后每次打开：开启动画 → 输入账号密码 → 主界面。

四步看起来多，但前两步是为了「锁」，后两步是为了「像你」。都不该省。

### 10.4 一句必须写死的警告

设定密码的界面上写着：**「密码只在这台设备上，不上传、不找回。忘了就打不开了。」**

这不是免责声明，是事实。我们没有服务器、没有邮箱、没有密保问题——**也正因为没有这些，才没人能替你打开。**

点「我忘了」只会得到一句：没有找回；如果你导出过备份，可以在新罐子里导入。

### 10.5 已知的代价

| 代价 | 说明 | 缓解 |
|---|---|---|
| 忘密码 = 全丢 | 加密的必然结果 | 写死在设定页；引导用户定期导出备份 |
| 每次保存要重加密 | 异步写，极端情况下最后一条可能来不及落盘 | 单次加密 < 5ms，窗口极小；P1 可改为「提交时 await」 |
| 打开变慢 | PBKDF2 20 万次约 0.1–0.3 秒 | 可接受，且正好发生在开启动画期间 |

## 12. 数据模型

```
Store         { cun:1, salt, iv, data }          // localStorage 里唯一的明文结构，内容是密文
Settings      { birthDate, gender, expectedYears=80, deviceLabel,
                reminderRule, silentStreak, lastGreetedOn, onboarded }
Jar           { code(16位), createdAt }            // 身份 + 密钥，不出本机
Person        { id, name, year, relation }        // 同行的人，只有年份，≤5
Entry         { id(UUID), weekIndex, date, text, mood(0-5),
                imageId?, tags[], createdAt, updatedAt }
Deleted       { [entryId]: timestamp }             // 墓碑，同步用
Image         { id, data, width, height, usedOn }  // usedOn 唯一 → 一天一张
GreetingLog   { date, module, kind, shown, responded, responseType }
```

- 移动端：SQLite，图片单独存文件并建索引。

- 导出格式：
  ```markdown
  # 2026 年 · 第 34 岁

  ## 第 1798 周（11月16日 – 11月22日）
  - 11月18日（心情 4）
    把阳台的桌子擦干净了，泡了杯茶，坐了一下午。
    ![](photos/2026-11-18.jpg)
  ```

## 16. 指标

### 14.1 北极星

**「有记录的周数 / 存活周数」** ——不是 DAU。没人需要每天开它。

### 14.2 关键指标

| 指标 | 目标 | 说明 |
|---|---|---|
| 引导完成率 | > 85% | 两步，越低说明问得太多 |
| 首周留存 | > 55% | 第一周内至少记录 2 次 |
| W4 留存 | > 30% | 行业日记类均值约 12–18% |
| 周记录率 | > 45% | 一年中有记录的周占比 |
| 中断后回归率 | > 35% | 中断 21 天后再打开 |
| 问候响应率 | > 40% | 看到问候后产生记录 |
| 同行添加率 | > 35% | 7 日内添加至少 1 人 |
| 每日图片使用率 | 15–35% | 过高说明「一天一张」没形成取舍 |
| 编辑使用率 | 10–25% | 过低说明入口太隐蔽，过高说明默认记录质量有问题 |
| 收揽使用率 | > 50% | 默认收揽即计数 |

### 14.3 反向指标

- 关闭提醒的比例
- 负向反馈中「焦虑」「压力」「不想看到」的频次
- 因「今天那张已用」而放弃记录的比例

## 17. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 收揽让人以为「丢数据」 | 高 | 段头永远显示条数；点一下即展开 |
| 六套文案写成六种刻板印象 | 高 | 只改语气不改意思；禁用身份标签称呼 |
| 编辑破坏「日记不可改」的心理契约 | 中 | 编辑不修改原日期；保留 updatedAt；P1 加版本历史 |
| 默认鼓励变成廉价打鸡血 | 高 | 鼓励 = 允许 + 认可，不是加油；过反模式表 |
| 一天一张引发挫败 | 中 | 待确认可反复更换；明确文案解释规则 |
| 数据丢失 = 人生丢失 | 极高 | 本地优先、纯文本、图片独立文件、导出不设限 |
| 分享需求 | 低 | 明确不做 |
